# Agent Teams

이 프로젝트에서 기능을 구현할 때 따르는 3단계 역할 분담과 각 역할의 프롬프트 규칙을
정의합니다. 한 사람(또는 하나의 에이전트)이 전체를 수행하더라도, 아래 순서와 책임
경계를 지켜 진행합니다.

## Planner — 요구사항 분석 및 아키텍처 설계

**책임**
- 요구사항을 읽고 애매한 부분은 가정을 한 줄로 명시한 뒤 진행한다.
- 변경이 필요한 파일과 이유를 구체적으로 나열한다 (예: `src/events.ts`에 CRUD 함수 추가,
  `src/supabaseClient.ts`는 재사용).
- 기존 구조(Mock 폴백, `.env` 기반 설정 등)와 충돌하지 않는 설계인지 확인한다.
- 새 모듈이 필요한지, 기존 모듈 확장으로 충분한지 판단한다.

**프롬프트 규칙**
- 코드를 작성하지 않는다. 파일별 변경 계획과 함수 시그니처만 제시한다.
- "왜 이 구조인가"를 한두 문장으로 설명한다.
- 불확실한 요구사항은 구현 전에 질문하거나 명시적으로 가정을 남긴다.

## Coder — TypeScript/Supabase 기능 구현

**책임**
- Planner의 설계를 따라 최소한의 코드로 구현한다. 요청받지 않은 리팩터링이나 추상화를
  추가하지 않는다.
- Supabase 호출은 항상 실패 가능성을 전제로 작성한다 — 네트워크 오류, 인증 실패,
  테이블 부재를 구분 없이 처리하되 Mock 폴백(`src/events.ts`의 `useMock` 패턴)과
  일관되게 동작해야 한다.
- 새 환경 변수가 필요하면 `.env.example`에도 함께 추가한다.
- 커밋 전 반드시 `npx tsc --noEmit`으로 타입 체크를 통과시킨다.

**프롬프트 규칙**
- 대상 파일과 라인만 정확히 수정한다 (Surgical Changes).
- 실제 파일을 먼저 읽은 뒤 편집한다 — 추측으로 기존 코드를 덮어쓰지 않는다.
- 구현 후 `npx tsx src/<file>.ts`로 직접 실행해 동작을 확인한다.

## Reviewer — 코드 품질 검증 및 타입 체크

**책임**
- `npx tsc --noEmit`으로 타입 오류가 없는지 확인한다.
- Mock 폴백이 실제로 트리거되는 경로(연결 실패, 인증 실패 등)를 검증한다.
- 에러 발생 시 콘솔 메시지가 원인을 명확히 알려주는지 확인한다.
- `.env`, `node_modules`, `dist` 등 커밋되면 안 되는 파일이 스테이징되지 않았는지
  `git status`로 확인한다.

**프롬프트 규칙**
- 발견한 문제는 파일 경로와 근거(구체적인 실패 시나리오)를 함께 제시한다.
- 사소한 스타일 의견보다 정확성·안전성 문제를 우선 보고한다.
- 통과 시에도 무엇을 검증했는지 간단히 기록한다.
